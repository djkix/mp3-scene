# Mp3 Scene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un site web privé, en un conteneur Docker, qui indexe une bibliothèque de releases MP3 scene montée en NFS et permet de la parcourir, de l'écouter et de la caster.

**Architecture:** Un serveur FastAPI sert une API JSON, les flux audio et une interface monopage statique sans build. Un index SQLite (WAL + FTS5) est alimenté par un scan manuel en deux phases (structure, puis tags ID3 en tâche de fond). La file d'attente et le lecteur vivent côté navigateur.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, SQLite/FTS5 (stdlib `sqlite3`), mutagen, argon2-cffi ; HTML/CSS/JS natif (modules ES), Google Cast Web Sender SDK ; pytest + httpx, `node --test` ; Docker.

**Spec:** `docs/superpowers/specs/2026-11-13-mp3-scene-design.md`

## Global Constraints

- Aucune écriture sous `/music`, jamais. Tout fichier est ouvert en lecture seule.
- Accès aux fichiers uniquement par identifiant d'index ; le chemin résolu doit être sous la racine de la bibliothèque.
- Toute route exige une session, sauf : `POST /api/login`, les fichiers statiques, `GET /cast/{track_id}`.
- Toute requête non-GET sous `/api/` doit porter l'en-tête `X-CSRF: 1`, sinon 403.
- Aucune liste ne renvoie plus de 100 éléments par requête.
- Interface en français uniquement ; thèmes clair et sombre via `prefers-color-scheme`.
- Pas d'étape de build côté interface, pas de framework JS, pas de dépendance npm.
- Dépendances Python d'exécution limitées à : `fastapi`, `uvicorn[standard]`, `mutagen`, `argon2-cffi`.
- Mots de passe jamais journalisés.
- Session : cookie `session`, `HttpOnly`, `Secure`, `SameSite=Lax`, 30 jours glissants.
- Anti-force brute : 5 échecs par identifiant ou par IP → blocage 15 minutes.
- URL de cast : validité 12 heures.
- Le dépôt n'existe pas encore : la tâche 1 fait `git init`. Un commit par tâche au minimum.
- Lancer les tests : `pytest -q` (Python) et `node --test static/js/` (JS).

## Review Focus

1. **Noms de fichiers ou de dossiers non UTF-8 sur le NAS** (octets latin-1) : le scan ne plante pas, la release est indexée et reste lisible. → test en tâche 3.
2. **MP3 sans tags, corrompu ou de taille nulle** : la phase tags le marque comme lu, continue, et n'y revient pas au scan suivant. → test en tâche 4.
3. **Recherche contenant des caractères spéciaux FTS5** (`"`, `*`, `(`, `-`, `AND`) : jamais d'erreur 500, résultats sensés. → test en tâche 6.
4. **Fichier disparu du NAS ou montage tombé entre le scan et la lecture** : 404 propre (flux, téléchargement, NFO), le zip saute le fichier manquant. → test en tâche 7.
5. **Extension en majuscules ou mixte** (`.MP3`, `.Mp3`, `.NFO`) : reconnue comme les minuscules. → test en tâche 3.

### Task 3: Scan — phase structure

**Files:**
- Create: `app/scanner.py`, `tests/test_scan_structure.py`

**Interfaces:**
- Consumes: `naming.parse_release_name`, schéma de la tâche 1.
- Produces:
  - `scanner.ScanError(Exception)`.
  - `scanner.scan_structure(conn, root: Path, now: float) -> dict` → `{"found": int, "added": int, "moved": int, "removed": int}`. Lève `ScanError` si `root` n'existe pas ou ne contient aucune entrée, **sans modifier la base**. Valide par lots (commit toutes les 500 releases) pour que les releases apparaissent pendant le scan.
  - Extensions comparées sans tenir compte de la casse. `DISC_RE = r"^(cd|disc|disk)[ _-]?(\d+)$"` (insensible à la casse).

Algorithme (non déductible des tests) :
1. Charger `{path: (id, mtime)}` des releases connues.
2. Parcours avec `os.scandir` en octets décodés par `os.fsdecode`. Pour un sous-dossier dont le chemin est une release connue et dont le `mtime` est inchangé : le marquer « vu » et **ne pas le lister**. `# ponytail:` un fichier ajouté dans `CD2/` d'un multi-disques ne change pas le mtime du parent → non détecté ; parade : `touch` du dossier, ou comparer aussi le mtime des sous-dossiers disque si le cas se présente.
3. Sinon lister le dossier. C'est une release s'il contient ≥ 1 `.mp3` directement, ou si ses sous-dossiers correspondant à `DISC_RE` en contiennent. Les sous-dossiers disque sont fusionnés (pistes avec `disc` = numéro, `relpath` = `CD1/fichier`) et ne sont pas parcourus séparément. Les autres sous-dossiers sont parcourus récursivement.
4. `category` = premier composant du chemin relatif ; `parent` = chemin relatif du dossier parent (`''` à la racine) ; `size` = somme de tous les fichiers du dossier ; `has_nfo` = présence d'un `.nfo`.
5. Release connue mais mtime changé : remplacer ses pistes, `tags_done=0`, garder `id` et `added_at`.
6. Fin de parcours : `gone` = connues non vues, `new` = trouvées non connues. Une release de `gone` dont le nom de dossier correspond à exactement une release de `new` (et est unique dans `gone`) est **déplacée** : `UPDATE path, parent, category` — `id`, `added_at`, pistes et tags conservés. Le reste de `gone` est supprimé, ainsi que ses favoris (`kind='release'` et pistes associées). Reconstruire `folders` : exactement les `parent` des releases et tous leurs ancêtres, hors racine (un dossier sans release en dessous, comme `Covers`, n'y figure pas).
7. `added_at` d'une nouvelle release = son `mtime` si `scan_state.first_scan_done = 0`, sinon `now`. Mettre `first_scan_done = 1` à la fin d'un scan réussi.

### Task 4: Scan — phase tags et lanceur

**Files:**
- Modify: `app/scanner.py`, `tests/conftest.py`
- Create: `tests/test_scan_tags.py`

**Interfaces:**
- Consumes: `scan_structure`, `db.connect`.
- Produces:
  - `scanner.scan_tags(conn, root: Path, should_stop: Callable[[], bool] = lambda: False) -> int` (nombre de pistes lues). Traite les pistes `tags_read=0` par lots de 200 avec commit ; toute erreur de lecture d'un fichier → champs `NULL`, `tags_read=1`. Quand toutes les pistes d'une release sont lues : `releases.genre` = genre de la première piste (ordre `disc, relpath`), `duration` = somme, `tag_artist` = artiste commun si toutes les pistes ont le même (sinon `NULL`), `tags_done=1`.
  - `scanner.Runner(settings)` : `start() -> bool` (`False` si un scan tourne déjà ; sinon lance un thread démon avec **sa propre connexion** qui enchaîne structure puis tags et tient `scan_state` à jour : `status`, `started_at`, `finished_at`, `releases_found`, `error`), `resume() -> None` (au démarrage : si des pistes `tags_read=0` existent, lance la phase tags seule ; remet `status='idle'` si un statut `structure` traîne d'un arrêt brutal), `stop() -> None`, `status(conn) -> dict` = colonnes de `scan_state` + `tracks_pending: int`.
  - Fixture `make_mp3(path, title=None, artist=None, genre=None, frames=40)` dans `conftest.py` : écrit `frames` trames MPEG-1 Layer III valides (en-tête `FF FB 90 64` suivi de 413 octets nuls = 417 octets, 128 kbit/s, 44,1 kHz), puis ajoute les tags avec `mutagen.id3.ID3` (`TIT2`, `TPE1`, `TCON`) si fournis.
